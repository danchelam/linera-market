# Linera 新窗口钱包冷启动恢复设计

## 背景与证据

2026-07-15 对新 HubStudio 窗口 `625421744`、`625421732`、`625421726`、`625421710` 进行了单线程稳定性测试。四个账号均在 Auto 启动前停在 `wallet_disconnected`。

现场证据显示两种独立故障：

1. `625421744`、`625421732`、`625421710` 首次启动时 provider 可注入，但 `personal_sign` 和 Linera Connect 都不产生 OKX 弹窗。关闭后第二次启动 `625421744`，同一 `personal_sign` 立即产生密码页并成功解锁，证明 OKX 扩展后台在首次冷启动时未正确初始化。
2. `625421726` 成功解锁密码后进入 `Signing…`。失败现场仍有针对 `app.linera.xyz` 的有效 OKX 确认页，但当前恢复代码在 Signing 重试前把它当成旧通知页关闭，导致 retry 不能恢复确认流程。

## 目标

- 新窗口冷启动无 OKX 弹窗时，在任何 Auto 或下注操作前自动重启一次。
- 一个账号在一次扫描中最多重启一次，禁止循环重启。
- `Signing…` 阶段优先处理已存在的 Linera OKX 确认页，只在没有有效确认页时点击 retry。
- 保持正式任务每日随机 4–7 轮、双边各 1 coin 和现有结算逻辑不变。

## 设计

### HubStudio 受控重启

HubStudio 适配层新增一个明确命名的受控重启接口。接口先调用 `/api/v1/browser/stop`，再调用现有 start 接口，仍传入 `--remote-allow-origins=*`。重启失败时保留具体阶段和 HubStudio 脱敏错误，不进行第二次重启。

重启只能由显式 Auto 任务的钱包冷启动恢复分支调用。只读就绪检测、Auto 已启动、已有持仓、结算和停止阶段不允许重启。

### 冷启动触发条件

首次就绪检测为 `wallet_disconnected` 时执行现有钱包恢复。仅当以下条件同时满足时重启：

- `run_auto=True`；
- Auto 会话尚未创建或启动；
- 恢复结果明确表示没有检测到 OKX 连接/确认窗口；
- 再次就绪检测仍为 `wallet_disconnected`；
- 本账号在本次扫描中尚未重启。

重启后重新连接 CDP。若没有普通页面，创建页面并导航到固定 Ride URL；若已有 Linera 页面则复用。然后重新执行就绪检测和一次钱包恢复。

### Signing 确认页选择

在初始 Connect 动作前仍清理旧的 `personal_sign` 通知页。但初始连接确认之后，如果 Linera 进入 `Signing…`：

1. 先在当前 context 中查找内容明确包含 `app.linera.xyz` 的 OKX notification 页；
2. 找到时直接交给多步确认处理器，不关闭、不重新点击 Signing；
3. 不存在有效页时才点击 `Signing…` / `Connect failed · retry`，并等待新弹窗；
4. 确认后仍以 Linera 前端的脱敏钱包地址和后端就绪状态作为最终成功证据。

### 失败与日志

日志区分首次恢复、冷启动重启、重启后恢复和 Signing 现有弹窗四个阶段。结果仍只记录脱敏钱包地址，不记录 Cookie、授权头、完整地址或响应正文。

重启后仍失败时，保留最后的标准就绪状态，原因包含首次恢复和重启后恢复的阶段摘要。

## 测试

- HubStudio stop 成功后 start 传入 CDP origin 参数，返回新端口。
- stop 或第二次 start 失败时不再重试。
- 只读检测不调用重启。
- 钱包首次无弹窗且复查仍断开时，Auto 模式恰好重启一次。
- 其他钱包失败原因、页面加载或后端错误不触发重启。
- 重启后没有普通页面时创建并导航 Ride 页。
- `Signing…` 出现且已有 Linera OKX 页时，不关闭弹窗、不点击 retry，直接确认。
- 没有现有 Linera OKX 页时，仅点击一次 retry。
- 全套单元测试通过后，对四个新窗口先各运行 1 轮集成验证，再运行单线程随机 4–7 轮稳定性测试。

## 非目标

- 不改变随机 4–7 轮与每轮双边各 1 coin 的任务策略。
- 不在 Auto 运行或结算阶段重启浏览器。
- 不对普通页面或后端错误扩大自动恢复范围。
- 不修改旧 Linera 任务目录。
