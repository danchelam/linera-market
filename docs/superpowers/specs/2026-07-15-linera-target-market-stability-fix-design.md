# Linera 目标市场稳定性修复设计

## 问题

账号就绪检测已经导航到并确认 `BTC 1m` Ride 页面。Auto 会话开始时又无条件执行一次 `page.goto`，导致新站点在钱包恢复后的 hydration 阶段可能恢复旧路由。保护逻辑随后以“BTC 1m 页面未能保持稳定”终止，因此 Auto 没有启动，也没有下注。

## 采用方案

让 `ensure_target_market()` 具备幂等性：

- 当前 URL 已是精确的 `BTC 1m` 路由时，不刷新页面，只连续观察路由稳定性。
- 当前 URL 偏离目标时，才导航到目标 URL，并继续观察。
- 观察期间如果发生路由漂移，最多按现有限制重新导航恢复。
- `Start Auto` 点击前继续执行最终 URL 校验；不放宽市场或周期安全限制。

## 不在本次范围

- 不改变下注金额、轮数或随机策略。
- 不移除钱包、后端、余额或 Auto 停止保护。
- 不批量启动 150 个账号。

## 验证

1. 先新增回归测试，证明正确目标页面调用 `ensure_target_market()` 时不会触发 `goto`；现有实现应失败。
2. 最小修改生产代码使回归测试通过。
3. 运行 `test_auto_page.py`，再运行完整测试套件。
4. 使用 `625421691` 执行固定 1 轮集成验证，确认 Auto 实际启动、完成或输出新的具体失败证据，并确保结束时 Auto 已停止。
